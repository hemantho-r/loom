# Grill Techniques

## Question bank (pick, don't run through)

- Problem: "What breaks today that this fixes? Who feels it?"
- Scope: "What is explicitly *not* part of this?"
- Constraints: "What can't change — deadline, API, data, team?"
- Success: "How will we know this worked in 30 days?"
- Failure: "What would make this a waste of time even if it ships?"
- Alternatives: "What did you already rule out, and why?"

## Follow-up ladder

1. Clarify: "Say more about ___."
2. Concretize: "Give me one real example."
3. Bound: "When does that *stop* being true?"
4. Commit: "So should I write down ___ as a requirement?"

Stop at rung 4 — either it becomes a brief line or an open assumption.

## Stop rules

Stop grilling when any is true:

- The brief's six lines can all be filled and the user nods.
- The user says "just decide for me" — record that as an explicit delegation, not a silent guess.
- 10 questions asked — summarize what you have and ask whether to continue.

## What not to do

- Never ask two questions in one message (the user answers the easier one).
- Never ask a question whose answer doesn't change the brief.
- Never re-ask something the user already answered — quote their words back.
